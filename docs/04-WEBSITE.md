# WEBSITE.md

> Documento canônico da arquitetura do site da Fyrmma.
>
> Define a estrutura da aplicação, o propósito de cada página, o fluxo de navegação, componentes reutilizáveis e diretrizes técnicas relacionadas à experiência do usuário.
>
> Este documento não contém copy institucional. Todo conteúdo textual pertence ao COPY.md.

---

# Objetivo do Site

O site da Fyrmma deve:

- comunicar claramente o posicionamento da empresa;
- explicar como resolvemos problemas operacionais;
- apresentar nossos serviços;
- demonstrar credibilidade;
- educar potenciais clientes;
- gerar contatos qualificados.

O site não existe apenas para apresentar a empresa.

Ele deve ajudar o visitante a entender seu problema, enxergar uma solução e iniciar uma conversa.

---

# Jornada do Usuário

Todo visitante deve conseguir responder rapidamente:

1. O que a Fyrmma faz?
2. Para quem?
3. Como trabalha?
4. Por que confiar?
5. Como entrar em contato?

Toda página deve contribuir para responder uma ou mais dessas perguntas.

---

# Estrutura do Site

## Home

Objetivo:

Comunicar imediatamente que a Fyrmma desenvolve sistemas web, automações e soluções com inteligência artificial para empresas de serviços, conduzindo o visitante até os serviços, metodologia e contato.

A Home deve responder rapidamente:

- o que fazemos;
- para quem fazemos;
- como trabalhamos;
- por que confiar na Fyrmma.

Seções:

- Hero
- Serviços
- Como Trabalhamos
- Diferenciais
- Tecnologias
- Perguntas Frequentes
- CTA Final

---

## Serviços

Objetivo:

Explicar claramente cada serviço oferecido.

Cada serviço deve possuir:

- descrição;
- benefícios;
- problemas resolvidos;
- processo;
- CTA.

---

## Projetos

Objetivo:

Demonstrar experiência através de projetos publicados.

Cada projeto deve conter:

- contexto;
- problema;
- solução;
- tecnologias utilizadas;
- resultados (quando possível).

---

## Blog

Objetivo:

Educar potenciais clientes e fortalecer SEO.

Os artigos devem estar organizados por categorias.

---

## Sobre

Objetivo:

Apresentar a empresa, seus princípios e sua forma de trabalho.

Não é uma página sobre os fundadores.

É uma página sobre a empresa.

---

## Contato

Objetivo:

Converter visitantes em oportunidades comerciais.

Deve conter:

- formulário;
- meios de contato;
- FAQ;
- CTA.

---

# Navegação

A navegação principal deve ser simples.

Itens:

- Início
- Serviços
- Projetos
- Blog
- Sobre
- Contato

Evitar menus excessivamente longos.

---

# Componentes Reutilizáveis

Preferir componentes reutilizáveis para:

- Hero
- CTA
- Cards
- FAQ
- Seções
- Depoimentos
- Grid
- Badges
- Breadcrumbs

---

# SEO

Toda página deve possuir:

- título único;
- meta description;
- Open Graph;
- URL amigável;
- heading hierarchy;
- dados estruturados quando aplicável.

---

# Performance

Priorizar:

- imagens otimizadas;
- lazy loading;
- fontes otimizadas;
- componentes leves;
- carregamento rápido.

---

# Acessibilidade

Todo o site deve seguir boas práticas de acessibilidade.

Incluindo:

- contraste adequado;
- navegação por teclado;
- textos alternativos;
- estrutura semântica;
- foco visível.

---

# Responsividade

Todo componente deve funcionar em:

- desktop;
- tablet;
- smartphone.

Responsividade não deve ser tratada como adaptação posterior.

---

# Componentização

Sempre priorizar:

- reutilização;
- consistência;
- modularidade.

Evitar componentes específicos quando um componente genérico resolver o problema.

---
