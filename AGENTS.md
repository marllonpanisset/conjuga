## Rules

- Do not duplicate documentation.
- Do not invent business rules.
- Do not create fictional projects or testimonials.
- Keep documentation as the single source of truth.
- Prefer modifying existing documents instead of creating new ones.
- Follow the existing architecture before introducing new patterns.
- Prioritize readability, maintainability and simplicity.

## Workflow

1. Read the relevant documentation.
2. Propose a solution.
3. Explain trade-offs when necessary.
4. Implement only what was requested.
5. Update documentation if the behavior changes.
